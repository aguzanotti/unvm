Módulo 1

¿Qué significa que un modelo sea abierto?

En el ecosistema de IA se usa con frecuencia la expresión open source para modelos cuyos pesos se pueden descargar. Sin embargo, publicar los pesos no implica necesariamente que también sean abiertos los datos de entrenamiento, el código completo, la documentación o todas las condiciones de uso.

Open-weight

Los pesos del modelo están disponibles para descargarlos y ejecutarlos. La licencia puede imponer condiciones específicas.

Open source AI

La apertura busca abarcar componentes y documentación necesarios para estudiar, usar, modificar y compartir el sistema, según una definición de apertura determinada.

Familias conocidas para explorar incluyen Qwen, Gemma, Llama, Mistral, DeepSeek, Phi y GLM. No existe un modelo mejor para todo: la elección depende de la tarea, el idioma, el hardware, la licencia y la calidad que necesitemos.

Idea clave: antes de descargar, revisar la licencia, la tarjeta del modelo, los idiomas soportados, la fecha de publicación y las limitaciones conocidas.

Un LLM no es un transcriptor

Un modelo de lenguaje (LLM) genera y transforma texto. Un sistema ASR (automatic speech recognition) convierte una señal de audio en texto. Son tareas relacionadas, pero suelen requerir modelos y herramientas diferentes. Una vez transcripto el audio, sí podemos usar un LLM local para resumir, clasificar o analizar el texto.

Módulo 2

¿Qué significa ejecutar IA en local?

En lugar de enviar cada consulta a un servicio externo, descargamos los archivos del modelo y realizamos la inferencia en nuestra propia computadora o en un servidor institucional.

Modelo y pesos

Aplicación local

Ejemplos de herramientas: LM Studio y Ollama para LLM; whisper.cpp para Whisper; NeMo o NeMo-Speech.cpp para modelos de voz como Parakeet. Los programas no son intercambiables: cada uno admite determinados formatos y arquitecturas.

Ventajas posibles

Mayor control sobre los datos, trabajo sin conexión después de descargar los modelos, experimentación, personalización y reducción de dependencia de APIs externas.

Responsabilidades

Gestionar actualizaciones, seguridad, permisos, almacenamiento, copias de respaldo, consumo energético y acceso a los equipos.

Ejecutar localmente no garantiza por sí solo privacidad absoluta: hay que comprobar que la aplicación no envíe telemetría o archivos a terceros, revisar la configuración de red y controlar quién accede al equipo.

Módulo 4 · práctica con LLM

Ejecutar modelos pequeños con LM Studio

LM Studio es una aplicación de escritorio para buscar, descargar y ejecutar modelos compatibles en la computadora. En equipos Linux, Windows y macOS ofrece un entorno gráfico para experimentar; utiliza llama.cpp para modelos GGUF y también ofrece soporte MLX en Apple Silicon.

Modelos para comenzar

Buscar variantes pequeñas de Qwen, Gemma, Llama, Phi o Ministral. Como punto de partida, explorar modelos de aproximadamente 2B–4B parámetros; luego probar 7B–8B si el hardware lo permite.

Elegir una variante

Buscar una versión compatible con LM Studio y con memoria suficiente para el equipo. Comenzar con un modelo pequeño y un contexto moderado; revisar los requisitos que informa la ficha.

  1. Instalar LM StudioDescargar la versión adecuada desde el sitio oficial. Abrir la aplicación al menos una vez.
  2. Buscar un modeloIr a Discover/Models y buscar, por ejemplo, Qwen, Gemma o Phi. Revisar tamaño, licencia, idioma y tarjeta del modelo.
  3. Elegir el modeloSeleccionar una variante pequeña y compatible. Revisar su ficha, tamaño, licencia e idiomas soportados.
  4. Descargar y cargarUna vez descargado, abrir el Model Loader. Ajustar el contexto inicial a 4096 u 8192 tokens y revisar el uso de memoria.
  5. Configurar GPU offloadProbar el ajuste automático o descargar tantas capas como permita la VRAM. Si falla, reducir el offload o el contexto.
  6. Probar y registrarUsar el mismo prompt en dos modelos y anotar latencia, tokens por segundo, memoria y calidad de respuesta.

Comandos opcionales de LM Studio

La interfaz gráfica alcanza para empezar. Para quienes prefieran la terminal, LM Studio incluye la CLI lms (tras iniciar la aplicación al menos una vez):

lms get qwen --gguf
lms ls
lms load <model_key> --context-length 4096 --gpu max
lms unload --all

Los nombres exactos disponibles cambian con el catálogo. La CLI permite estimar memoria con lms load --estimate-only <model_key>. Si el modelo no cabe en VRAM, probar el ajuste automático o reducir el contexto.

¿Qué observar durante la prueba?

  • Tiempo hasta la primera respuesta.
  • Velocidad de generación (tokens por segundo).
  • RAM y VRAM utilizadas.
  • Calidad de las respuestas en español.
  • Errores, alucinaciones y límites del contexto.
No comparar modelos solo por el número de parámetros o por un benchmark. La calidad depende de la tarea, el idioma, el prompt, la versión del modelo y el hardware.
Módulo 5 · práctica con audio

De audio a texto con Python en Google Colab

Para una primera experiencia, conviene hacer la transcripción en Google Colab: permite ejecutar código Python desde el navegador, instalar bibliotecas y aprovechar una GPU cuando está disponible, sin configurar el entorno de la computadora. Usaremos Whisper mediante la biblioteca faster-whisper.

Una distinción importante: esta práctica no es ejecución local. El audio y el procesamiento se realizan en el entorno de Colab, por lo que hay que evitar subir entrevistas o materiales sensibles sin autorización y sin revisar las condiciones institucionales. Más adelante se puede explorar la ejecución local con whisper.cpp o Parakeet.

Práctica guiada en Colab

  1. Abrir un cuadernoEntrar a colab.new ↗ e iniciar un cuaderno nuevo.
  2. Elegir el entornoEn Entorno de ejecución → Cambiar tipo de entorno de ejecución, seleccionar T4 GPU si está disponible. También puede ejecutarse en CPU, aunque será más lento.
  3. Instalar la bibliotecaEjecutar la siguiente celda:
!pip -q install faster-whisper

Subir un audio de prueba

Usar un archivo breve (por ejemplo, WAV, MP3 o M4A) propio o con licencia y consentimiento adecuados. Al ejecutar la celda, Colab abrirá un selector de archivos.

from google.colab import files

uploaded = files.upload()
audio_path = next(iter(uploaded))
print("Archivo:", audio_path)

Cargar Whisper y transcribir

El ejemplo selecciona automáticamente GPU o CPU. El modelo small es un punto de partida razonable para probar; se pueden comparar luego base, small y medium, teniendo en cuenta el tiempo y los recursos disponibles.

import torch
from faster_whisper import WhisperModel

device = "cuda" if torch.cuda.is_available() else "cpu"
compute_type = "float16" if device == "cuda" else "int8"

model = WhisperModel("small", device=device, compute_type=compute_type)
segments, info = model.transcribe(
    audio_path,
    language="es",
    vad_filter=True
)

texto = []
for segment in segments:
    linea = f"[{segment.start:.1f}s - {segment.end:.1f}s] {segment.text}"
    print(linea)
    texto.append(linea)

with open("transcripcion.txt", "w", encoding="utf-8") as f:
    f.write("\n".join(texto))

Descargar el resultado

files.download("transcripcion.txt")

La transcripción incluye marcas temporales aproximadas. Conviene revisar nombres propios, siglas, vocabulario técnico, puntuación y pasajes con ruido o voces superpuestas. La salida automática es un borrador, no una transcripción validada.

Módulo 6

Del equipo personal al campus universitario

La ejecución local puede escalar desde una notebook hasta servidores institucionales con GPU. Las universidades pueden instalar modelos y aplicaciones en infraestructura propia, ofrecer servicios a sus comunidades y establecer reglas de acceso, protección de datos y mantenimiento.

En una computadora

Experimentación individual, prototipos, análisis preliminares y actividades de formación.

En un laboratorio

Workstations GPU compartidas, entornos reproducibles y asistencia técnica para equipos de investigación.

En un centro de cómputo

Servidores GPU, almacenamiento, colas de trabajo, contenedores y servicios accesibles desde el campus.

Como servicio institucional

Interfaces web y APIs internas para transcripción, asistencia documental y otras aplicaciones.

Un ejemplo: Caracola

Caracola, desarrollada en el ámbito de la Universidad Nacional de Córdoba, ilustra cómo una necesidad concreta —transcribir audio— puede convertirse en un servicio apoyado en infraestructura universitaria de cómputo. El caso permite discutir privacidad, capacidad institucional, mantenimiento, disponibilidad y acceso a herramientas de IA.

Módulo 7 · trabajo final

Actividades para experimentar

Práctica A · Comparar dos modelos pequeños en LM Studio
  1. Descargar dos modelos pequeños de familias diferentes (por ejemplo, Qwen y Gemma), con tamaños y requisitos de memoria comparables.
  2. Usar el mismo prompt en español para ambos: resumir un texto breve sin agregar información externa.
  3. Comparar precisión, claridad, tiempo de respuesta y memoria utilizada.
  4. Repetir con un contexto mayor y registrar qué cambia.
Entregable: tabla comparativa breve con familia, modelo, tamaño, contexto, hardware y observaciones.
Práctica B · Transcribir un fragmento de audio
  1. Elegir un audio de prueba propio o con licencia/consentimiento adecuado, de 2–5 minutos.
  2. Ejecutar Whisper o una variante Parakeet compatible con el idioma.
  3. Revisar manualmente la transcripción y marcar errores, nombres propios y pasajes dudosos.
  4. Comparar el resultado automático con una transcripción corregida.
Entregable: transcripción revisada y breve registro del modelo, configuración, tiempo y errores observados.
Práctica C · Del texto al análisis asistido
  1. Tomar una transcripción anonimizada o un texto público.
  2. Usar un LLM local para proponer un resumen temático.
  3. Solicitar que separe citas textuales de interpretaciones.
  4. Verificar cada resultado contra el texto original.
Entregable: memo analítico breve con trazabilidad de las decisiones y correcciones humanas.
